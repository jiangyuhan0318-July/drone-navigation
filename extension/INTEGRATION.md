# 坐姿 / 摔倒检测 —— 对接规范

把队友已实现的 **坐姿检测**、**摔倒检测** 封装进无人机导航的手势控制模式。
本文件是对接口契约: 队友功能接入后, 识别结果以**统一输出接口**暴露,
上层(执行器 / OpenClaw / 网页)零改动。

## 1. 视频流入口

无人机摄像头经桥接链路推成 **共享 RTSP 流**, 多个消费者可同时接入:

```
rtsp://127.0.0.1:8554/crazyflie-drone
```

- 手势识别、坐姿检测、摔倒检测、网页直播都消费同一路流, 互不打架。
- 队友功能若自己取流, 直接指向上面 RTSP; 否则由识别服务抽帧喂给它。

## 2. 统一输出接口 (HTTP JSON)

两个识别服务分别暴露, 端口固定, 输出格式即契约:

### 坐姿服务 — `GET http://127.0.0.1:8701/posture`

```json
{
  "state": "sitting_ok | slouching | leaning | standing | null",
  "confidence": 0.87,
  "features": {"trunk_angle": 8.2, "head_tilt": 12.1, "knee_angle": 95.0, "trunk_len": 0.42},
  "fresh_s": 0.03,
  "frames": 1234
}
```

### 摔倒服务 — `GET http://127.0.0.1:8702/fall`

```json
{
  "state": "absent | standing | falling | fallen | null",
  "hold": 12,
  "confidence": 0.91,
  "features": {"trunk_angle": 72.0, "hip_y": 0.63},
  "fresh_s": 0.03,
  "frames": 1234
}
```

字段约定:
- `state`: 语义状态标签(**契约核心**)。`null` = 画面无人。状态迁移用上升沿消费。
- `fresh_s`: 距最后推理帧的秒数。**> 3 视为链路断了, 结果不可信**。
- `confidence`: 0~1(模型置信度或关键点可见度)。
- `features`: 可解释特征, 调试/调阈值用, 格式可扩展。

## 3. 队友功能接入方式 (三选一)

| 方式 | 队友交付 | 说明 |
|---|---|---|
| A. 模型文件 | onnx/pth/tflite 模型 (+ 前处理说明) | 识别服务加载模型推理, 输出映射到 `state` |
| B. 推理代码 | import 可用的类/函数 (输入帧, 输出状态) | 识别服务调用队友接口, 输出映射到 `state` |
| C. 现成 HTTP 服务 | 队友已起 `:端口/xxx` 返回状态 | 识别服务转发/规范化成上面的统一格式 |

> 无论哪种方式, 识别服务对外的 `/posture` `/fall` JSON **格式不变**,
> 执行器和 OpenClaw skill 感知不到后端换了。

## 4. 动作链路 (安全门控)

```
识别服务 (:8701/:8702)  →  执行器  →  POST /api/copilot/command
        →  飞行门控校验 →  无人机
```

- 坐姿: 绑定 `sitting_ok → takeoff`(飞机在身边降落, 检测到坐姿后起飞)。
- 摔倒: 默认**只告警不动作**(人员安全事件, 先通知), 飞行动令映射可选。
- 所有飞行动令走 `/api/copilot/command` 门控链路, 与手势/网页按钮同一条,
  **不绕过任何安全机制**。

## 5. 对接检查清单

- [ ] 队友功能读 `rtsp://127.0.0.1:8554/crazyflie-drone` 或接受逐帧喂入
- [ ] 输出能映射到本文 `state` 语义(坐姿四态 / 摔倒四态)
- [ ] 提供 `confidence`(0~1); 没有就置 1.0
- [ ] 输出带时间戳, 可算 `fresh_s`
- [ ] 画面无人时输出 `null`/`absent`(不是卡在上一个状态)
